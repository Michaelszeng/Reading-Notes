## Assembly & Computer Architecture
**Assuming fixed amount of "work"... how to make it run faster?**
4 Stages:
1. Pre-processing
	- Expand macros
	- Still C code... stored in `.i` files
2. Compiling
	- Convert C to ASM (`.s` files)
3. Assembling
	- Convert to `.o` object files
	- Also possible to "disassemble" -- turn `.o` back into ASM code for debugging/investigation
4. Linking
	- Merge all objects, libraries into 1 executable

**x86-64 ISA**
- Registers: `%xxx`
	- 16 general-purpose registers (i.e. `r0-r15`)
		- Many names for 64-bit, 32-bit, 8-bit versions of the register
	- Flag register
	- Instruction pointer register: `%rip`
	- XMM, YMM registers
- Instructions
	- Format: `<opcode> <operand_list>` (0, 1, 2, or 3 operands)
		- i.e. `addl %edi, %ecx`
		- AT&T Syntax: `<opcode> A, B` performs `B <op> A -> B` (B is the result)
		- Intel Syntax: `<opcode> A, B` performs `A <op> B -> A` (A is the result)
	- Opcode suffixes:
		- 1 char at the end of an instruction that specifies what datatypes it is dealing with
			- i.e. `q` = 64-bit integer
		- If suffix is missing, inferred from the given register types
	- Conditionals
		- Branch/jumps rely on the result of the previous compare
		- i.e.
		```
		cmpq TODO
		jne .LBB7_1  # Checks if the last comparison is True
		```
		- RFLAGs
			- `ZF`, `CF`
			- Operations write into RFLAG
			- Jumps can also check RFLAGs?
- Memory addressing modes
	- Immediate Values: `movq $106, %rdi`  (sets `%rdi` equal to 106)
	- `movq %rax, %rdi`  Move btwn registers
	- `movq 0x106 %rdi` Move from address to `%rbi`
	- `movq (%rax), %rdi`, Move from address specified by `%rax` into `%rdi`
	- `movq 106(%rax), %rdi` Move from the address specified by 106 offset from the value in `%rax` to `%rdi` 
	- `movq 106(%rip), %rdi` TODO
	- Base indexed scale displacement: `movq 106(%rdi, %rdx, 8), %rax`
		- Basically a single optimized instruction for array access at index `%rdx` (`rdi` is the ptr of the base of teh array; `%rax` is where the access value in the array is stored); `8` here is the size of any array element
	- Jumps
		- `jmp`
		- `j<condition>`

**x86 Architecture**
- 3 core architectural ideas:
	- Parallelism (instruction-level parallelism, multi-code)
	- Locality (use caching to save data that's been recently used, hoping that it'll be used again)
	- Branch Prediction (predict branches and run in advance)
- Pipelining
	- Pipeline stalls -- if an instruction fails to finish in its designated clock cycle
	- Structured Hazard: 
		- some ops (multiplication, division, etc.) take multiple cycles
		- Fetch multiple instructions per cycle; 
	- Control Hazard: Delayed 
	- Data Hazard: 
	- Dealing w/Hazards:
		- Stalling
		- Bypassing
		- Out-of-order Execution: execute later one before earlier one if it has no dependencies
		- Register Renaming: remove dependency by changing which register you're using
			- Intel Haswell has only 16 registers accessible in code, but they map to 168 physical registers to avoid dependencies
		- Speculation
		- SMT: simultaneous multi-threading
			- 2 instruction streams running at the same time; if one stalls, switch to running the other

## Bentley Rules
**4 Categories of Optimization for reducing "Work"**
Data Structures
- *Packing*: store >1 data value in 1 machine word
```C
	typedef struct {
		int year: 13;  // 13-bit field
		int month: 4;
		int dat: 5;
	} date_t;
```
- *Encoding*: convert data into form that requires fewer bits
- *Augmentation*: add extra info to data structure to make common ops faster
	- i.e. adding both head/tail ptrs to linked list if doing lots of list concat
- *Caching*: avoid unnecessary recomputation
- *Precomputation*: calculate + store lookup table ahead of time to avoid doing them at "test-time"
- *Compile-time Initialization*: Same as pre-computation, but at compile-time (i.e. just hard-coding values)
	- Metaprogramming: Writing program whose output is source code (or i.e. code for a large lookup table) that you paste into your actual program
	- Multi-stage Programming: 
		- `static_var<type>` are evaluated in stage 1 and replaced w/ compiled values
		- `dyanmic_var<type>` are evaluated in stage 2 (using stored `static_var<type>` values)
		- i.e. (left: pre-stage 1, right: post-stage 1 -- notice how `setup()` gets compiled into constants)
			<center><img src="School Supplements/6.106_multistage_program.png" alt="" style="width:600px; margin-top: 10px"/></center>	
- *Sparsity*: Avoid storing and computing with 0's
	- Compressed Sparse Rows (CSR)
			<center><img src="School Supplements/6.106_sparsity.png" alt="" style="width:400px; margin-top: 10px"/></center>	
		- `rows`: each index corresponds to a row; value indicates start of a slice into `cols`
		- `cols`: parallel list w/ `vals`; specifies the column that each val goes in (in given row) 
		- `vals`: parallel list w/ `cols`; specifies val (in given column + row)
		- Storage $O(n + nnz)$
		- mat-vec-mul $O(nnz)$
				<center><img src="School Supplements/6.106_sparse_mat_vec_mul.png" alt="" style="width:400px; margin-top: 10px"/></center>	
Logic
- *Constant Folding & Propagation*: during compilation, eval constant expressions, substitute results into code (usually done by compiler)
- *Common Sub-expression Elimination*: avoid computing same expression multiple times; instead, cache and substitute (usually somewhat done by compiler)
- *Algebraic Identities*: simplify algebraic formulas
- *Create a Fast Path*: run a quick check first (that passes most of the time) before running complete, thorough check (if the first check fails)
- *Short-Circuiting*: stop/break as soon as you know the answer
- *Ordering Tests*: run tests first that are more likely to allow breaking/stopping before running other tests
	- i.e. Skydio's sample selection
- *Combining Tests*: replace branching/casework (incurs overhead) with computation + lookup array or a switch statement
Loops
- *Loop Unrolling*: unroll multiple iterations of loop into a single iteration
	- avoid overhead from branching/control
	- allow compiler to do more optimization within a single iteration
- *Hoisting / Loop-Invariance Code Motion*: move loop-invariant code (i.e. code that generates the same result every iter of the loop) outside of the loop
- *Loop Fusion / Jamming*: if you have multiple loops over same indices, combine them into 1 loop
Functions
- Functions incur branching/control overhead
- *Inlining*: Don't use function; just inline its body
	- Reduces control flow overhead + allows compiler to do more optimization
	- The compiler does this for you using `inline void func(...)` keyword
	- Basically always good, unless this induces massive code size blowup (i.e. if the function is called in a loop w/tons of iters)
- *Tail-Recursion Elimination*: If the last call in a function is a recursive self-call, avoid the self-call by simply branching back to the top of the function
- *Coarsening Recursion*: Increase size of the base-case to reduce amount of recursion
	- i.e. for small inputs, use non-recursive, faster special case to solve. Only call recursion for large inputs


## C Tricks
- NOTE: good practice to always use `unsigned` types if doing bit hacks
- Get an all 1's mask: `-1` (recall 2's complement representation of negative numbers)
- Set k<sup>th</sup> bit: `x | (1 << k)`
- Clear k<sup>th</sup> bit: `x & ~(1 << k)`
- Toggle the k<sup>th</sup> bit: `x ^ (1 << k)`
- Extract a bit field: `(x & mask) >> shift`
	- (`mask` indicates the bit field to be extracted, `shift` shifts this bit field in the LSB)

- Set a bit field: `(x & ~mask) | (y << shift)`
	- (`mask` indicates the bit field, `y` is the value to set it to)
				<center><img src="School Supplements/6.106_set_bit_field.png" alt="" style="width:525px; margin-top: 10px"/></center>	
	- Safer version: `(x & ~mask) | ((y << shift) & mask)`

- Circular Buffer (more like a modulo $2^k$): 
	- `mask = ((1 << k) - 1)`
	- `x = (x + 1) & mask`

- Swapping 2 variables
	- `x = x ^ y`
	- `y = x ^ y`
	- `x = x ^ y`
	- Why this works: `XOR` is its own inverse: `(x ^ y) ^ y = x`
	- HOWEVER: bad for instruction-level parallelism; must happen serially
	- Using a temporary variable is actually faster
- Min of 2 ints
	- Simple method: `r = (x < y) ? x : y`
	- `r = y ^ ((x ^ y) & -(x < y))`
		- `(x < y)` returns all 1 if `x < y`, else 0. Then, the minus sign turns this into all 1's (an all-1 mask) or all 0's.
		- if `x < y`:
			- `r = y ^ (x ^ y) = x`
		- if `x > y`:
			- `r = y ^ ((x ^ y) & 0) = y`
		- Good if branch is unpredictable, you want to avoid branching
	- NOTE: in practice, `r = a ? x : y` are optimized by compiler to use `cmov` instruction, so are actually very fast
- Modular Addition
	- `r = (x + y) % n`, where `0 <= x < n`, `0 <= y < n`
	- Want to avoid branching, and want to avoid division
		- `z = x + y`
		- `r = z - (n & -(z >= n))`
			- If `z >= n`, then `r = z - n`. If `z < n`, then `r = z`.

## Review
- Intuition of subtracting 1:
	- `10110000` --> `10101111`
	- essentially remove the last 1, then replace all the trailing 0's with 1's
- 2's complement:
	- Leading 1 is negative valued; all other digits positive valued
	- To find 2's complement representation, this is a simple trick: `-x = ~x + 1`
		1. Represent `+x` in binary
		2. Flip all the bits
		3. Add 1
	- i.e.: to represent -28:
		- +28 in binary: `00011100`
		- ~28: `11100011`
		- ~28 + 1: `11100100`   <--   -28 in binary
- Speculative branch prediction
	- Keeps history of running this branch in the past -- repeats most common from history
	- Note: branch mis-prediction is costly -- on order of an L2 cache miss

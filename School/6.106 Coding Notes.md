## Compiler Instrumentation
*TIX* (Tool Instrumented Executable)
*CSI*: Cilk's instrumentation framework
- User-written *Hooks*/functions injected by compiler into code
- Compiled into LLVM IR
- KEY IDEAS:
	- Instruments 6 IR objects: loads, stores, basic blocks (any sequence of straight-line code), function entry points, function exits, call instructions
	- Define hook functions that interact with all instances of these 6 IR objects
		- hook functions receive unique CSI ID corresponding to the IR object + properties (`prop`) struct that is supplied by the compiler
			- NOTE: CSI IDs are automatically assigned as ints starting from 0
		- Each `prop` struct is 64 bits in total
	- At the end of the program, *forensic table* maps each CSI ID/IR object back to line + column in source code
CSI Infra:
- Simply compile with `-fcsi` flag
- Initialization:

## LLVM IR
What is LLVM IR?
- "Pseudo-assembly" -- closer to assembly, but still assumes infinite registers, human syntax, special /higher-level instructions
	- Gets translated line-by-line to assembly (but the compiler must still decide how to pick instructions, registers, etc.)
Syntax
- `;...`: This line is a comment
- Header:
	- `source_filename` original source (.c) file
	- `target triple` target platform (`x86_64-linux`)
	- `target datalayout` describes ABI/layout details (pointer sizes, alignment rules, etc.)
- `%...`: variable
	- Note: all LLVM IR vars can only be assigned once (equivalent to `const` C vars)
- `i1`, `i8`, `i64`, `ptr`, `<16 x i8>`: type definitions (boolean, 8-bit int, pointer, vector of 16 8-bit ints)
- General instruction format: op-code, return type, arguments
	- i.e. `%add = add nsw i64 %var1, %var2`
	- Note: `nsw` = "no signed wrap", allows compiler to assume that overflow will not happen
- Functions: `define ... void/return_type ... @func_name(type ... %a, type ... %b)...`
	- Parameter attributes:
		- i.e. `type nocapture noundef readonly %b`
		- (read-only, not undefined, not captured/stored outside of function call)
- Branching
	```
	%cmp = icmp slt i64 %n, 2
	br i1 %cmp, label %return, label %if.end
	```
	- Integer comparison (`slt` = "signed less than") between 2 `i64`'s, `%n` and `2`. Output (boolean) stored in `%cmp`
	- If `%cmp` is true, jump to label `return`, else, jump to label `if.end`
	- Types of comparisons:
		- `icmp` (integer comparison):
			<center><img src="School Supplements/6.106_LLVM_IR_icmp_types.png" alt="" style="width:325px; margin-top: 10px"/></center>
		- `fcmp` (float comparison):
			- Roughly the same operations, but start with `o` or `u` for "ordered" vs "unordered", where "ordered" means that neither arg can be NaN
	- `br label %return`: unconditional jump to label `return`
	- `phi` blocks:
					<center><img src="School Supplements/6.106_LLVM_IR_phi.png" alt="" style="width:350px; margin-top: 10px"/></center>
		- i.e. `%retval = phi i64 [ %var1, %label1 ], [ var2, %label2 ]`
		- Meaning: if we got to `return` block from `label1 ` block, then set `%retval` to `%var1`. If we got to `return` block from `label2` block, then set `%retval` to `%var2`.
- Functions are split into blocks denoted by no-indent labels
	- Each block ends with `br` (branch), `ret` (return), or other terminator instructions
	- [Example](https://godbolt.org/z/xKhj73bdK):
					<center><img src="School Supplements/6.106_LLVM_IR_function_example.png" alt="" style="width:750px; margin-top: 10px"/></center>
- Loads/Stores:
	- `%7 = load i8, ptr %arrayidx, align 1`:  Load type `i8` from pointer `%arrayidx`
	- `store i8 %add, ptr %arrayidx1, align 1`: Store type `i8` with value `%add` to pointer `%arrayidx1` 
	- `%wide.load = load <16 x i8>, ptr %0, align 1`: Vector load
	- `store <16 x i8> %4, ptr %2, align 1`: Vector store
	- `align 1`: tells compiler it can only assume that data are 1-byte aligned

## Tooling
- make clean; make DEBUG=1
	- Makefile includes `-gdwarf-2 -DDEBUG -O0` when DEBUG=1```
		-gdwarf-2 generates debugging symbols, -DDEBUG defines the preprocessor symbol "DEBUG"
		(so that you can use "#ifdef DEBUG" in your code), and -O0 disables compiler optimizations, 
		so that the binary generated more directly corresponds to your source code.```
- Run with gdb enabled: `telerun gdb -ex run -ex bt -batch ./BINARY
	- GDB prints stack trace + line number
	- `-ex run` --> run automatically
	- `-ex bt` --> backtrace; tells GDB to print stack trace
	- `-batch` --> batch mode (non-interactive mode; causes GDB to exit after program finish/error)
- Run with ASAN: `make ASAN=1`
	- Compiler tool
	- Identify invalid memory access -- buffer overflows, use-after-free, double free, invalid allocations/memsets
		- Does NOT detect using uninitialized/unset memory
- Run with MSAN: make `MSAN=1`
	- Identify uses of uninitialized memory (i.e. `malloc` or `aligned_alloc` without `memset`ing the alloc'ed memory)
	- Note: Read the trace bottom up; start from the heap allocation at the bottom, then the trace (going upward) shows the propagation of the uninitialized value through the program
- Run with UBSAN: make `UBSAN=1`
	- Catch undefined behavior at runtime (signed int overflow, divide by zero, shifting too many bits, null pointers, out of bounds, etc.)
	- Not related to memory debugging
- Run with Valgrind: `telerun valgrind ./BINARY`
	- Does not require re-compiling; runtime only
	- Note: Valgrind only detects memory bugs related to outputs/prints
- Run with Cachegrind: `telerun valgrind --tool=cachegrind --cache-sim=yes --branch-sim=yes <binary> <binary args>`
	- Simulates branch prediction/cache misses (using the architecture of your machine)
	- `I refs` = instruction references (how many instructions in final build)
	- `D refs` = data references (how many data accesses in final build)
- Run with Gcov: 
	- Line execution counter
	- Add flags `-fprofile-arcs -ftest-coverage` to `CFLAGS` and `LDFLAGS`
	- Compile and run (this will generate .gcda, .gcno files)
	- Run `llvm-cov gcov FILE.c` (this will generate .gcov file)
		- This .gcov text file indicates execution counts (`#####` indicates the line was never run)
	- VERY HELPFUL for performance optimization -- figure out which lines contribute most to runtime
- `perf`
	- `telerun perf record PROGRAM`
	- `perf report -f -i perf.data`
		- `-f` = "force" (avoid "perf.data not owned by current user or root" error)
		- `-i` = specify input path (default will use `data.perf` in current dir)
	- Must pass `-g` flag to `clang` during compilation (generate debug symbols, allowing `perf` & `gdb` to associate machine code w/source code)
	- NOTE: due to out-of-order execution, perf may not always accurately blame which line of C code is causing the slowdown. May be something before the line that perf highlights (usually, perf will highlight something trivial like `add`, but it is really a `mov` from before. The add just got pushed forward while `mov` was taking multiple cycles).
- Assembly inspection
	- `objdump -dS BINARY > a.out`
	- Also, perf lets you see assembly
 - Assertions
	- Only run with DEBUG=1 (so use liberally)
	- `#include "./tbassert.h"`

Compiling
- clang-6106 -E -FLAG file.c
- `CFLAGS`: compilation flags
- `LDFLAGS`: linking flags
- Link-time optimization: add `-flto` to both `LDFLAGS` and `CFLAGS`
	- Allow optimizations (i.e. inlining) between .c files
- Optimization level `O0` - `O3`. `O0` default (no optimization at all). Vectorization unlocked at `O2`.

GCC Vector Extension to C
- New type `vfloat_t` defined: `typedef float vfloat_t __attribute__((__vector_size__(64)));`
	- Vector of floats
	- 64 is the total size (in bytes) of the vector
	- We can define vector variables in C: 
		- A single vector of floats: `vfloat_t vec;`
		- An array of vectors of floats: `vfloat_t vec_array[10];`
	- Operations (i.e. `+`, `*`, `&`, `|`, `==`, `!=`) are elementwise
	- Individual elements in vector can be accessed:
		```C
		typedef float vfloat_t __attribute__((__vector_size__(64)));
		#define VEC_SIZE (64 / sizeof(float))
		
		for (int e = 0; e < VEC_SIZE; ++e)
			vec[e] = A[i + e];  // Initialize vec w/ consecutive elements of float array A starting at index i
								 // NOTE: this would actually compile as a vector load from address &A[i]
			vec[e] = A[i];  // Intialize vec to have all elements equal to A[i]
							 // NOTE: this would compile as a vector broadcast (vbroadcast)
		```
- Example: Matrix Multiplication
```C
typedef float vec_t __attribute__((vector_size(64)));
#define VEC_SIZE (64 / sizeof(float))

void matmul(float *restrict C, const float *restrict A,
                 const float *restrict B, unsigned int row_length,
                 unsigned int size) {

  for (unsigned int j = 0; j < size; j += VEC_SIZE) {  // iterate through cols (unrolled 16x)
    for (unsigned int i = 0; i < size; i += 16) {  // iterate through rows
	    // Initialize vectors to hold C values for row i, cols j through j + 16
        vec_t c0, c1, c2, c3, c4, c5, c6, c7, c8, c9, c10, c11, c12, c13, c14, c15;
        
        // Load current C values, store in to C vectors
        // This compiles as 16 vector load operations
        for (int e = 0; e < VEC_SIZE; e++) c0[e] = C[(i+0)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c1[e] = C[(i+1)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c2[e] = C[(i+2)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c3[e] = C[(i+3)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c4[e] = C[(i+4)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c5[e] = C[(i+5)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c6[e] = C[(i+6)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c7[e] = C[(i+7)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c8[e] = C[(i+8)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c9[e] = C[(i+9)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c10[e] = C[(i+10)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c11[e] = C[(i+11)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c12[e] = C[(i+12)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c13[e] = C[(i+13)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c14[e] = C[(i+14)*row_length + j + e];
        for (int e = 0; e < VEC_SIZE; e++) c15[e] = C[(i+15)*row_length + j + e];

		// Iterate through 
        for (unsigned int k = 0; k < size; k++) {
            // Initialize vectors to hold A values for row i, cols j through j + 16
            vec_t a0, a1, a2, a3, a4, a5, a6, a7, a8, a9, a10, a11, a12, a13, a14, a15;
            
            // Broadcast A values (for each vector, all values in the vector are the same)
            // This compiled as 16 vector broadcast instructions
            for (int e = 0; e < VEC_SIZE; e++) a0[e] = A[(i+0)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a1[e] = A[(i+1)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a2[e] = A[(i+2)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a3[e] = A[(i+3)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a4[e] = A[(i+4)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a5[e] = A[(i+5)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a6[e] = A[(i+6)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a7[e] = A[(i+7)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a8[e] = A[(i+8)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a9[e] = A[(i+9)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a10[e] = A[(i+10)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a11[e] = A[(i+11)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a12[e] = A[(i+12)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a13[e] = A[(i+13)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a14[e] = A[(i+14)*row_length + k];
            for (int e = 0; e < VEC_SIZE; e++) a15[e] = A[(i+15)*row_length + k];
            
            // Load B vector once for the entire loop
            vec_t b_vec;
            for (int e = 0; e < VEC_SIZE; e++) b_vec[e] = B[k*row_length + j + e];
            
            // Perform c += a * b (using the same b_vec for the entire loop) -- elementwise
            c0 += a0 * b_vec;
            c1 += a1 * b_vec;
            c2 += a2 * b_vec;
            c3 += a3 * b_vec;
            c4 += a4 * b_vec;
            c5 += a5 * b_vec;
            c6 += a6 * b_vec;
            c7 += a7 * b_vec;
            c8 += a8 * b_vec;
            c9 += a9 * b_vec;
            c10 += a10 * b_vec;
            c11 += a11 * b_vec;
            c12 += a12 * b_vec;
            c13 += a13 * b_vec;
            c14 += a14 * b_vec;
            c15 += a15 * b_vec;
        }
        
        // Store results into C
        // This is compiled as 16 vector stores
        for (int e = 0; e < VEC_SIZE; e++) C[(i+0)*row_length + j + e] = c0[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+1)*row_length + j + e] = c1[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+2)*row_length + j + e] = c2[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+3)*row_length + j + e] = c3[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+4)*row_length + j + e] = c4[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+5)*row_length + j + e] = c5[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+6)*row_length + j + e] = c6[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+7)*row_length + j + e] = c7[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+8)*row_length + j + e] = c8[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+9)*row_length + j + e] = c9[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+10)*row_length + j + e] = c10[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+11)*row_length + j + e] = c11[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+12)*row_length + j + e] = c12[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+13)*row_length + j + e] = c13[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+14)*row_length + j + e] = c14[e];
        for (int e = 0; e < VEC_SIZE; e++) C[(i+15)*row_length + j + e] = c15[e];
    }
  }
}
```
- IMPORTANT: typically, you want to manually-unroll loops 16x to use all 16 vector registers
- When GCC Vector Extension is useful:
	- Lane-wise `+`, `-`, `*`, `/`
	- Bitwise ops: `&`, `|`, `~`, `<<`, `>>`
	- Comparison: `==`, `!=`, `<`, `>`
	- Has a `__builtin_shuffle` function to re-order elements, but this is only performant if the passed-in mask is constant. At risk of compiler generating bad scalar code.

## Practical Techniques
**High Level Strategy**
1) Start from Perf Reports -- just fix what's slow

Inlining
- Compilers func. do some inlining by default if `-fno-inline` is not set in `CFLAGS`
- However, to force inline a function, add: `inline __attribute__ ((always_inline)) void foo()`

Loop Unrolling: `#pragma unroll Nlocked threit `

Vectorization
- Change Loop Order
	- If inner loop is very vectorizable (simple computation or independent memory reads)
		- Note that there is no vectorized memory write operation
- Break loops into two (one that contains all vectorizable ops, the other that contains serial ops)
- Remove branching if's/continue's; turn them into boolean-calculations (and potentially break the loop into 2 as well)
- Force vectorization: `#pragma clang loop vectorize(enable) interleave(enable)`
- `CFLAGS += -Rpass=loop-vectorize -Rpass-missed=loop-vectorize` to provide vectorization report
- Use `a = __builtin_assume_aligned(a, 16);` within a function to tell compiler `a` is 16-byte aligned in memory, allowing further optimization in that function. 
	- Note that the caller must allocate `a` using `aligned_alloc` (i.e. `uint8_t *a = aligned_alloc(16, SIZE * sizeof(uint8_t));`).
	- Or, if `a` is local stack variable (not dynamically allocated), caller must create `a` using `uint8_t a[SIZE] __attribute__((aligned(16)));`
	- NOTE: use 64 instead of 16 for AVX512 instructions (which use 64-byte vectors instead of 16-byte)
	- NOTE: aligned moves in ASM have the form `movdqa` while unaligned moves have the form `movdqu` (so you can tell from the assembly whether alignment worked or not)
	- NOTE: this isn't strictly better. Can introduce more overhead if you are doing unaligned accesses to `a`, then compiler needs to add runtime checks to see if aligned instructions can be used or not
- Re-structure data structures so that they involve more contiguous data accesses, fewer gather/scatter ops
	- Note: if you do require gather/scatter ops, often better to use unvectorized gather/scatter instructions
- Manual vectorization using GCC Vector Extension
- Manual vectorization using compiler intrinsics
- Vectorization Report:
	- Vectorization width: number of elements in vector
	- Interleaved count: unrolling factor in vectorized loop
- `restrict` keyword:
	- Can be used on pointer declarations (in func. arguments or local variables) to promise compiler that, in scope of that variable, the pointer is the *only* way to access the pointed-to object.
	- Then the compiler can skip aliasing checks --> unlocks more vectorization (if the pointer was involved in a loop)
		- i.e.:
		```C
		for (int i=0; i<size; i++) {
			*res += x[i];
		}
		```
		- Compiler only knows this is safe to vectorize if `res` and `x` are not aliases of each other/memory does not overlap. To do so, use `restrict`.
	- Note: in practice, alias checks between `void* a` and `void* b` looks like comparing end of a < start of b or end of b < start of a. If either are true, vectorization is safe.

Pre-fetching
- Use `_mm_prefetch(addr, _MM_HINT_X)`
	- Options: 
		- `_MM_HINT_T1`: L1, L2, L3
		- `_MM_HINT_T2`: L2, L3
		- `_MM_HINT_T3`: L3
		- `_MM_HINT_NTA`: Non-temporal cache slot (usually L1) 
- Run this in a loop, during the iteration before the data at `addr` is actually needed.
- This way, the data is already in cache when it is needed. The cache loading time is overlapped with other compute-heavy operations in the previous loop

Re-organized data structures to avoid strided gather/scatter operations -- make vectorized accesses to fields contiguous in memory

Pre-allocate/avoid dynamic memory allocation in loops or recursion

`-ffast-math` CFLAG: turns on multiple math flags; disregards many floating point rules (can re-order associative operations for better vectorization, ignore NaNs/signed zeroes) --> often allows more vectorization
- Note that floating-point math isn't exactly associative bc of precision differences

General strategy for parallelization: turn any for loop into divide-and-conquer parallelization; hopefully this allows you to skip some work too

## C Tricks
- `##`: Token-pasting macro; can be used in `#define` statements
	- i.e. `n_ ## x` gets compiled to the variable `n_A` if `x` is passed in as `A`
- Logic/Arithmetic on Pointers:
	- First cast to `(uintptr_t)`
